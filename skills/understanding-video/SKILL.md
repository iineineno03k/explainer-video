# 理解用のページと動画を作る

理解の材料は **ナレッジのページが正本**。動画はそのページを読み上げる派生物で、台本の場面ごとに出典の節を書く。AI の頭の中や作業フォルダから作らない (根拠をたどれず、次の人が同じものを作れない)。台本の形・コマンド・台詞のつながりのレビューは `explainer-script` skill に従う。

聞き手は対象を知らない人。業務やシステムは人の理解を超えて複雑なので、細部より先に **全体感** を渡す。

- **全体の中のどこか**：対象が全体の流れのどこにあり、前後と何をやりとりしているか。
- **何のためにあるか (Why)**：それがないと誰が何に困るか。
- **中で何が起きて、手元に何が出て、誰が何を決めるか (What)**。

細部 (画面の項目・例外・計算式) は、全体感が入ってから。全体の図にない話を先にしない。

そのうえで、ページも動画も **見る人の認知負荷を減らす** ことを常に優先する。

- **知りたいことを構造化して渡す**：作る前に、見終わって答えられる問いを「全体 → 部分」の順に 3〜5 個 (要れば 1 段だけ小さな問い) に決める。ページの冒頭と動画の最初の画面にその一覧を置き、節・場面を問いに 1 つずつ対応させ、最後に答えを並べ直す。
- **図には見方を付ける**：図ごとに「この図の見方」(何が軸・色・矢印・レーンか、どこから読むか) を 1〜2 行添える。動画では中身の前に見方を言う。
- **画面の写しは、見る所を囲む**：スクショをそのまま貼らない。追ってほしい所を赤枠 (順に追うなら ①②③) で囲み、何を見る枠かを書く。動画では台詞ごとに枠を動かし、枠の外は暗くする (explainer の既定)。

人に見せたあとの指摘で手順を足していった記録 (頼み方のひな形・見たときに確かめること) は、同じフォルダの `lessons.md`。見せる前に、そこの「見たときに確かめること」を自分で確かめる。

## 0. 何本に分けるか

- **最初の 1 本は全体像**：誰が客で、何を売り (作り)、お金・書類・データがどう流れ、その中でこのシステム (または対象) がなぜあるか。5〜8 分。
- 次から **箱 (業務やシステムのまとまり) ごとに 1 本**。どの箱も、全体像と同じ図の上で「いまここ」を強調してから入る。
- 1 本 5〜10 分に収まらないなら箱を割る。

## 1. 材料を集める

- 依頼者が指した資料は読み切る。そのうえで、そのリポジトリのナレッジ (Wiki・docs・用語集) を読み、足りなければ一次資料 (議事録・ヒアリングの文字起こし・仕様書・画面の録画・ソース) をあたる。指されていない大きな資料群は、`grep` で関係する所を探してから、その前後を読む。
- 画面の話をするときは、実物の画面の写しを使う。**ない画面は実際に操作して撮る** (文章で補わない)。
- 帳票・Excel・図面は実物を使う。ただし実物をそのまま置いてよいのは、**ページ・台本を置くリポジトリも、動画の置き場も、見られるのが守秘の約束の内側の人だけ**のとき。public なリポジトリ・外へ出す動画・社外の人が見る場所では、先に出せないもの (顧客名・個人名・連絡先・金額・図面) を決め、伏せるか架空の値で描き直す。どちらか分からなければ、置く前に依頼者に確かめる。
- 個人情報 (氏名・連絡先・住所) が写った画面は、チーム内でも伏せてから置く。
- 実物が手に入らないものは「まだもらえていない」とページに書く。

## 2. ページを書く (正本)

ナレッジの置き場所の決まりに従ってページを置く。冒頭に「このページで分かること」(0 で決めた問いの一覧) を置き、次の順で書く。**各節に図か実物を 1 枚以上付ける** (文字だけの節を作らない。人は図がないとレビューできない)。

1. **全体の中のどこか**：全体の流れの図で対象を強調し、前後と切れ目 (何が起きて、誰から誰へ何が渡るか) を示す。続けて **登場する相手** (台詞に出てくる立場：客・取引先・社内の部署など) を、お金・書類・データの向きの図で、1 件の実際の数字を使って定義する。聞き手は立場の違いからつまずく。
2. **何のためにあるか (Why)**：それがないと誰が何に困るか、を 2〜3 個。
3. **中で何が起きるか (What)**：担い手ごとのレーンで流れを描き、各段で出るもの (書類・データ・通知) を図に置く。部署や商品で中身が違うなら、流れの図にどの部署の流れかを書き、違うものは段ごとに比べる図を足す。値引・依頼・交渉・承認などの行為には、誰から誰へかを書く。
4. **画面ごとに** (システムがあるとき)：「どこを押すか (メニューとボタン) → 何が出るか (Excel・PDF・番号) → 誰が何のために使うか → いまの不満」。全画面を 1 枚に並べた図を先頭に置き、続けて画面ごとの写しと出るものの実物。システムの外 (Excel・紙・メール) で作るものも同じ形で並べる。不満が聞けていない画面は「聞けていない」と書く。
5. **出るものを目的で分けると**：相手に約束する／社内で判断する／後ろへ渡す／経営が見る、のように目的で分けた図。
6. **次へ何が渡るか**：切れ目で渡る番号・金額・予定と、受け取る箱。

全体像のページは 1・2 と「箱の並び」だけでよい (箱の中は箱のページへリンク)。

図は生成元 (HTML を書く Python など) を台本のフォルダ (`videos/<名前>/diagrams/`) に置き、ページの隣に PNG で描く (Chrome の headless)。

- 1 枚の図で言うことは 1 つ。見方が 1 つに決まる形にする (流れは左から右、担当はレーン、強調は 1 色、1 枚に要素 7 個まで)。図の下に「この図の見方」を書く。
- 画面の写し・帳票は、見る所を赤枠で囲んだ版をページに置く (生成元で元の画像に枠を描く)。枠の横に何を見る枠かを書く。
- 描いたら画像を開いて、文字の重なり・はみ出し・矢印が文字を横切っていないか、**見方の 1 行だけを読んで図が追えるか**を自分で見る。ナレッジに lint があれば流す。

## 3. 台本を起こす

- `videos/<名前>/script.yaml` と `readings.yaml`。形は `explainer-script` skill と explainer の README。読みの辞書は前の動画のものを写して足す (同じ案件で 1 つに育てる)。
- 場面はページの節の順。場面ごとに `# 出典: <ページ>#<節>` を書く。**ページにないことは言わせない** (言いたくなったら先にページに足す)。
- 最初の場面は、この動画で分かること (問いの一覧) を `card` で見せる。次の場面で全体の図を出し、見方を言ってから「いまここ」を赤枠で示す。全体像の動画なら、箱の並びを示して終える。
- 画像の場面では、画像の中身を話す台詞には必ず `boxes` を付ける (枠のないまま画面の中身を話さない)。
- 画面の場面は「どこを押す (赤枠) → 何が出る → 誰が何のため → 不満 (`point` に `不満：…`)」の順。メニューの場所は場面の `point` に出す。
- 数字は台詞で言い、画面にも `point` で出す。赤枠の `label` は枠の幅に収まる短い語にする。縦長の帳票は `zoom` で話す所に寄せる。
- 最後の場面で、最初の問いの一覧に答えを付けて並べ直す (全体の中の位置・出るもの・不満・次へ渡すもの)。
- 書き終えたら `explainer lines` で台詞だけを通しで読む。相づちが直前の相手の発言に答えているか、まだ紹介していないものを「さっきの」と言っていないか、問いに答えないまま次に移っていないかを見る。台詞を足したら前後を必ず読み直す。

## 4. サブエージェントにレビューさせる

書いた本人の読み直しでは見落とす (何にも答えていない「そうよ」、立場の取り違え、1 つの部署の例を全体の話にする、が出た)。build の前に、**この会話を引き継がないサブエージェントを 2 本、並べて立てる**。どちらにも、台本を書いた理由や会話の経緯は渡さない。

| レビュー | 指示書 | 渡すもの |
|---|---|---|
| 台詞のつながり | `explainer-script` skill の `review.md` | 指示書のパス・台本のパス |
| 中身 (ページと合っているか・誰の話か) | この skill の `review-content.md` | 指示書のパス・台本のパス・正本のページのパス |

- 頼み方は「指示書を読んでその通りにレビューし、表で返す。台本もページも直さない」。
- 「直す」は全部直す。「よくなる」と「迷う」は自分で選ぶ。ページ側を直す所が出たら、ページを先に直す。
- 直したら同じ 2 本で再レビューする。**回すのは 3 回まで**。3 回目の「直す」を直したら、もう回さずに build する (4 回目より後の指摘は、ほとんどが前の回の直しで入れた台詞から出る)。
- 直すときは、台詞を足すより、削る・短くするほうを選ぶ。
- 人の指摘で台詞を足した・入れ替えたときも、build の前にこの 2 本をやり直す。

## 5. 確かめて作る

```bash
cd videos/<名前>
explainer lines script.yaml     # 台詞を通しで並べる
explainer preview script.yaml   # 音声なしの画
explainer build script.yaml     # mp4 と字幕
```

- preview の画を何枚か開き、その画だけを見て見る所が 1 か所に決まるかを確かめる。赤枠の位置・ラベルの切れ・字幕のはみ出しも見て直す。
- 数字はページの出典 (画面の写し・帳票) と突き合わせる。
- build の SRT を読み、読み間違いそうな語を `readings.yaml` に足す。用語の読みは、現場 (会議) での呼び方に合わせる。
- mp4 はリポジトリに入れない (`out/` は commit しない)。**チームがリンクで開ける場所** (共有ドライブなど、チームが決めた場所) に置き、同じ名前で上げ直してリンクを変えない。手元のファイル・AI のチャット画面の添付・限定公開の動画サイトには置かない (チームが開けない・転送を止められない・片付けに人手が要る)。
- 置き場と見られる範囲が決まっていなければ、上げる前に依頼者に確かめる (置き場・見られる人・動画に入っている社内の材料)。社内の材料が入った動画を、誰でも見られる場所に置かない。
- 台本のフォルダの README (動画の一覧) とページの冒頭から、動画のリンクを張る。

## 6. 見せる

- 最初に見せるのは、頼まれた中身の動画 (道具の動作確認のサンプルではない)。リンクで渡す。
- 人に見てもらうのは「合っているか・大きな抜けがないか」だけ (関門にしない)。ページ (図)・台本・preview の数枚を添える。
- 見た人の分からなかった所は、ページに足してから台本を直す。指摘とそれで足した手順は `lessons.md` の形でチームの記録に残すと、次の箱で同じ指摘が減る。
