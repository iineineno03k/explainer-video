# 頼み方と、見たときに確かめること

理解用のページと動画を人に見せたときに出やすい指摘と、それを先に防ぐ決まり。この skill の手順は、こうした指摘から足していった。

## 頼み方のひな形

そのまま貼って `<対象>` と `<置き場>` を変えればよい。

```text
understanding-video の skill で、「<対象 (全体像 か 箱の名前)>」の理解用のページと動画を作って。

- まず全体感。<対象> が全体の中のどこにあって、何のためにあるのか (Why・What) を先に。
- 見終わって答えられる問いを先に構造化して、最初に見せて、最後に答えで閉じて。
- 図には見方を付けて、画面の写しは見る所を枠で囲んで。認知負荷を減らすことを最優先に。
- どの画面で何を押すと、どんな Excel・帳票が出て、それを誰が何に使っていて、何が不満か。
- 台詞に出てくる立場 (客・仕入れ先・社内の部署など) は、最初に図で定義して。
- 部署で流れが違うなら、どの部署の流れかを書いて、違う部署は比べて。
- 台本ができたら、build の前にサブエージェントにレビューさせて。
- 動画は <置き場> に置いて、リンクをちょうだい。
```

## 見たときに確かめること

AI 同士のレビューでは出にくく、人が見て初めて出やすい指摘。見せる前に自分で確かめ、見る人もまずここを見る。

| 確かめること | こうなっていると指摘される |
|---|---|
| 頼まれた中身の動画か | 道具の動作確認のサンプルを先に見せてしまう |
| チームが開ける場所に置かれ、リンクで渡しているか | 手元で再生しただけ・AI のチャット画面に置いただけで、チームが見られない |
| 全体の中のどこで、何のためにあるかが先に来ているか | いきなり画面や手順の細部から始まり、何の話か分からない |
| 何が分かる動画かが、問いの形で先に示され、最後に答えで閉じているか | 見終わっても、何が分かればよかったのか分からない |
| 図に見方が添えてあり、画面の写しは見る所が枠で囲まれているか | 図やスクショを見ても、どこをどう追えばよいか分からない |
| 画面のどこを押すと何が出て、誰が何の目的で使い、何が不満か、がそろっているか | 画面の名前だけ出て、仕事の中での意味が分からない |
| 用語の読みが現場の呼び方と合っているか | 社内略語を、会議での呼び方と違う読みで話す |
| 登場する立場の違いが分かるか | 「客」と「仕入れ先」など、似た立場の違いがつかめない |
| 交渉・依頼などの行為が、誰から誰へか分かるか | 値引の交渉相手が取り違えて聞こえる |
| 1 つの部署・1 つの場合の例を全体の話にしていないか | 一部の部署だけの流れを、全体の流れとして話す |
| 台詞が前の発言に答えているか | 説明役が突然「そうよ」と言い、話がつながらない |

## 決まりにした理由

| 起きやすいこと | 決まり |
|---|---|
| 動画の作業から始めて、根拠をたどれなくなる | 動画の前にナレッジのページと図を作る。ページが正本、動画は派生物。台本の場面ごとに出典の節を書く |
| 図を自前で描き直して、実物とずれる | チーム内で見せる動画なら、図面・録画・帳票の実物を使う |
| 文字だけの節は、人がレビューできない | ページの各節に図か実物を 1 枚以上付ける |
| 指摘のたびに台詞を差し込み、前後がずれる | 台詞を足したら通しで読み直す。build の前にサブエージェント 2 本でレビューする |
| レビューを何回も回すと、前の回の直しが次の指摘を生むだけになる | レビューは 3 回まで。直しは足すより削る |
| 置き場を何度も変えて、見せるまでの往復が増える | 最初からチームが開ける置き場に置き、同じ名前で上書きしてリンクを変えない |

## 振り返りの要点

- 人の指摘は、ほとんどが「見る人が分からない」所に出る。AI 同士のレビューは台詞のつながりと数字の食い違いには効くが、「この言葉で引っかかる」は人が 1 回見ないと出にくい。
- 直しは足すより削るほうが安い。
- 全体感が先にあると、箱の動画は最初の 1 場面 (全体の図で「いまここ」) だけで聞き手が位置をつかめる。
